# TECH — Commercial agentic daily learning flow

## Current system
- Hub React app: `lifeos-hub/src/Hub.tsx`, `lifeos-hub/src/data.ts`, `lifeos-hub/src/hub.css`.
- Design-system deck card: `lifeos-ds/src/components/DeckCard.tsx` and CSS.
- Public static build: `tools/lifeos_vercel_build.py` builds public artifacts, copies `public/output/learn` to `public/learn`, then builds `/hub`.
- Knowledge graph: `public/output/learn/knowledge-graph.json` generated by existing tools.

## Implementation plan
1. **Account/profile menu**
   - Replace top-right XP-only pill with account button.
   - Add a fixed account panel with Google sign-in, profile stats, completed quest list, graph preview/link, notes, send-to-phone, and pricing.
   - Read existing localStorage progress schema; avoid backend dependency.

2. **Google auth-ready path**
   - Add client-side Google Identity Services loader.
   - Read public client ID from `VITE_LIFEOS_GOOGLE_CLIENT_ID` or `window.LIFEOS_GOOGLE_CLIENT_ID`.
   - Store only decoded profile display fields locally; do not store secrets.

3. **Stripe pricing-ready path**
   - Add three plan cards in account menu.
   - Read public Payment Link URLs from Vite env/window config.
   - Missing links produce a user-visible notice; no secret keys in repo.

4. **Phone handoff**
   - Use `navigator.share` when available.
   - Fall back to copying `/hub` URL.

5. **Morning agent picks**
   - Use the graph-ranked deck and a daily hash to present three compact recommendations inside the quest section.
   - Clicking a pick selects it in the swipe deck and scrolls to deck.

6. **Mythic art pipeline**
   - Add `tools/lifeos_mythic_art.py` to read the public graph and write:
     - `public/output/learn/art/mythic/<node-id>.svg`
     - `public/output/learn/art/mythic-art-manifest.json`
   - Each manifest record includes node metadata, generated-image target path, and a detailed Fable/Claude-mythos prompt.
   - Update Vercel build to run this after graph/lessons generation and before copying to `public/learn`.
   - Update hub deck lessons with `artUrl` so cards use the generated fallback art.

## Risks
- Google sign-in on static Vercel is identity-only unless a backend verifies tokens.
- Stripe Payment Links are sufficient for checkout redirects but not entitlement enforcement.
- 594 SVGs add static files; keep them simple and deterministic.
- Full generated-image assets may increase deploy size later; prefer optimized `.webp` when real generated images are added.

## Validation
- `npm run build` in `lifeos-hub`.
- `python tools/lifeos_mythic_art.py build`.
- `python tools/lifeos_vercel_build.py`.
- Check graph node count equals art manifest count.
- Playwright checks:
  - main sections are only `quest`, `deck`
  - account menu opens and contains Google, pricing, send-to-phone, completed quests, graph, notes
  - Stripe buttons show configured/missing-link behavior
  - no horizontal overflow at 320/390/768/1280 px
  - deck still has only No/Read controls
